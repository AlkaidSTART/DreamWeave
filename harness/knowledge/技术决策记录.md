# Dreamweave AI 生图平台 - 技术决策记录 (ADR)

## 概述

本文档记录项目中的关键技术决策及其背景和理由，帮助后续开发者理解架构设计的意图。

## 决策记录

### ADR-001: 测试框架选择 - Vitest vs Jest

**状态**: 已接受

**日期**: 2026-07-21

**背景**:
- 项目使用React 19和Next.js 16
- Jest与React 19存在兼容性问题
- 需要一个现代化的测试框架

**决策**:
选择Vitest作为测试框架

**理由**:
- Vitest提供更好的React 19支持
- Vitest基于esbuild，启动和运行速度更快
- Vitest提供Jest兼容API，迁移成本低
- Vitest原生支持ES模块

**影响**:
- 需要更新PRD中的package.json scripts
- 需要更新TDD中的Jest配置示例
- 测试命令保持兼容

### ADR-002: 实时通信方案选择 - SSE vs WebSocket

**状态**: 已接受

**日期**: 2026-07-21

**背景**:
- 需要实时推送图片生成进度
- 主要是服务器向客户端单向推送

**决策**:
选择SSE（Server-Sent Events）作为实时通信方案

**理由**:
- SSE实现简单，基于HTTP协议
- 适合单向数据流（进度推送）
- Next.js内置支持SSE
- 浏览器原生支持，无需额外库

**边界考虑**:
- SSE连接在反向代理后可能有超时限制
- 需要配置心跳机制保持连接
- 高并发场景下需要考虑资源消耗

**备选方案**:
- WebSocket: 适合双向通信，实现复杂度较高

### ADR-003: 文件存储方案选择 - 本地存储 vs 云对象存储

**状态**: 已接受（混合方案）

**日期**: 2026-07-21

**背景**:
- 需要存储用户上传的图片和生成的结果
- 开发环境和生产环境需求不同

**决策**:
开发环境使用本地存储，生产环境使用云对象存储

**理由**:
- 本地存储在开发环境简单方便
- 云对象存储支持水平扩展和高可用性
- 实现存储抽象层，支持无缝切换

**影响**:
- 需要实现存储抽象层（StorageService）
- 生产环境需要配置云存储服务（如AWS S3、阿里云OSS）
- 需要实现文件生命周期管理

---

### ADR-004: 数据持久化方案 - Redis vs 独立数据库

**状态**: 已接受（当前使用Redis）

**日期**: 2026-07-21

**背景**:
- PRD中未定义独立数据库层
- 所有状态依赖Redis/BullMQ
- 历史记录查询需求可能增加

**决策**:
当前阶段使用Redis作为唯一数据存储，未来根据需求引入PostgreSQL

**理由**:
- Redis已作为BullMQ的依赖存在
- 任务状态和队列数据天然适合Redis
- 减少技术栈复杂度
- 历史记录查询需求当前较低

**演进方向**:
- 当历史记录查询需求增加时，引入PostgreSQL
- 使用Redis作为缓存层，PostgreSQL作为持久化层
- 实现数据同步机制

### ADR-005: 前端框架选择 - Next.js vs Remix

**状态**: 已接受

**日期**: 2026-07-21

**背景**:
- 需要一个全栈框架
- 需要服务端渲染和API路由
- 需要良好的开发者体验

**决策**:
选择Next.js 16作为前端框架

**理由**:
- App Router功能完善，支持Server Components
- 内置API路由，无需额外配置
- 自动优化（图片、字体、脚本）
- 生态成熟，社区活跃

**关键特性**:
- Server Components默认启用
- Route Handlers API路由
- SSE支持
- React 19兼容

---

### ADR-006: CSS框架选择 - Tailwind CSS 4 vs CSS Modules

**状态**: 已接受

**日期**: 2026-07-21

**背景**:
- 需要现代化的CSS方案
- 需要快速开发和良好的设计系统支持

**决策**:
选择Tailwind CSS 4作为CSS框架

**理由**:
- CSS-first配置，无需JavaScript配置文件
- 原子化CSS，开发效率高
- 零运行时开销
- 主题配置灵活（@theme指令）

**关键特性**:
- `@import "tailwindcss"` 导入
- `@theme` 定义设计令牌
- 自定义工具类和变体
- 响应式设计支持

---

### ADR-007: 队列系统选择 - BullMQ vs RabbitMQ

**状态**: 已接受

**日期**: 2026-07-21

**背景**:
- 需要异步任务处理
- 需要并发控制和重试机制
- 需要与Redis集成

**决策**:
选择BullMQ作为队列系统

**理由**:
- 基于Redis，部署简单
- 并发控制完善
- 重试机制灵活（fixed、exponential）
- 任务管理功能丰富

**关键配置**:
- 并发数: 4（可配置）
- 重试次数: 3
- 退避策略: exponential
- 任务自动清理: 24小时

---

### ADR-008: Worker进程管理方案

**状态**: 已接受

**日期**: 2026-07-21

**背景**:
- 需要独立的Worker进程处理异步任务
- 需要进程监控和自动重启

**决策**:
使用PM2进行进程管理

**理由**:
- 支持多进程管理
- 自动重启崩溃的进程
- 监控进程状态和资源使用
- 支持集群模式

**配置**:
- 主进程: Next.js应用（cluster模式）
- Worker进程: 4个实例（fork模式）
- 自动重启: 启用
- 日志管理: 启用
