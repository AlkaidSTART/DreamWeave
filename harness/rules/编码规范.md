### 1.1 配置要求

### 1.2 类型定义规范

- **优先使用接口**: 使用`interface`定义对象类型，`type`定义联合类型和工具类型
- **避免any**: 禁止使用`any`类型，使用`unknown`替代
- **类型守卫**: 使用类型守卫缩小类型范围
- **泛型约束**: 泛型必须有明确的约束

```typescript
interface User {
  id: string;
  name: string;
}

type Result<T> = {
  success: boolean;
  data?: T;
  error?: string;
};

function isUser(value: unknown): value is User {
  return typeof value === 'object' && value !== null && 'id' in value;
}
```

### 1.3 变量声明

- **const优先**: 优先使用`const`，仅在需要重新赋值时使用`let`
- **禁止var**: 禁止使用`var`声明变量
- **解构赋值**: 优先使用解构赋值提取对象/数组属性

```typescript
const { name, age } = user;
const [first, second] = array;
```

## 2. 组件规范

### 2.1 Server Components vs Client Components

- **默认Server Components**: 所有组件默认为Server Components
- **显式声明**: 需要客户端交互时，在文件顶部添加`'use client'`
- **混合使用**: Server Components可以导入Client Components，反之不行

```tsx
// Server Component (默认)
async function Page() {
  const data = await fetchData();
  return <ClientComponent data={data} />;
}

// Client Component (显式声明)
'use client';

function ClientComponent({ data }) {
  const [count, setCount] = useState(0);
  return <div>{data}</div>;
}
```

### 2.2 组件设计原则

- **单一职责**: 每个组件只负责一个功能
- **可复用性**: 设计可复用的通用组件
- **Props最小化**: 只传递必要的Props
- **条件渲染**: 使用三元运算符或逻辑运算符进行条件渲染

```tsx
function Button({ children, disabled }) {
  return (
    <button
      disabled={disabled}
      className={`px-4 py-2 rounded ${disabled ? 'opacity-50' : 'hover:opacity-90'}`}
    >
      {children}
    </button>
  );
}
```

### 2.3 Hooks使用规范

- **自定义Hooks**: 以`use`开头命名
- **Hook规则**: 只在组件顶层调用Hook
- **useState**: 状态变量命名使用`set`前缀
- **useEffect**: 明确依赖数组，避免无限循环

```typescript
function useCounter(initialValue = 0) {
  const [count, setCount] = useState(initialValue);
  
  const increment = () => setCount(c => c + 1);
  const decrement = () => setCount(c => c - 1);
  
  return { count, increment, decrement };
}
```

## 3. API 规范

### 3.1 Route Handlers规范

- **文件命名**: 使用`route.ts`作为API路由文件
- **HTTP方法**: 使用`GET`/`POST`/`PUT`/`DELETE`函数
- **参数验证**: 使用Zod或类似库验证请求参数
- **错误处理**: 使用try-catch包裹所有异步操作

```typescript
import { NextRequest, NextResponse } from 'next/server';

export async function POST(request: NextRequest) {
  try {
    const body = await request.json();
    
    const job = await queue.add('generate', body);
    
    return NextResponse.json({ jobId: job.id }, { status: 200 });
  } catch (error) {
    return NextResponse.json(
      { error: 'Internal Server Error' },
      { status: 500 }
    );
  }
}
```

### 3.2 响应格式规范

```typescript
interface ApiResponse<T = unknown> {
  success: boolean;
  data?: T;
  message?: string;
  error?: string;
}

interface PaginatedResponse<T> {
  data: T[];
  page: number;
  pageSize: number;
  total: number;
}
```

### 3.3 错误处理规范

| HTTP状态码 | 使用场景 |
|------------|----------|
| 200 | 请求成功 |
| 400 | 请求参数错误 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

## 5. 服务层规范

### 5.1 服务类设计

- **类命名**: 以`Service`后缀命名
- **单一职责**: 每个服务类只负责一个业务领域
- **依赖注入**: 通过构造函数注入依赖
- **异步优先**: 所有外部调用必须是异步的

```typescript
class PromptService {
  private apiClient: ApiClient;
  
  constructor(apiClient: ApiClient) {
    this.apiClient = apiClient;
  }
  
  async refine(prompt: string): Promise<string> {
    const response = await this.apiClient.post('/refine', { prompt });
    return response.data.refinedPrompt;
  }
}
```

### 5.2 错误处理

- **自定义错误**: 使用自定义错误类区分错误类型
- **错误传播**: 不要吞掉错误，向上传播
- **错误日志**: 在服务层记录错误日志

```typescript
class ServiceError extends Error {
  constructor(message: string, public code: string) {
    super(message);
    this.name = 'ServiceError';
  }
}
```

## 6. 队列层规范

### 6.1 Queue配置

- **队列命名**: 使用描述性名称（如`image-generation`）
- **默认配置**: 在`src/queue/queue.ts`中配置默认选项
- **任务选项**: 为每个任务类型定义默认选项

```typescript
import { Queue } from 'bullmq';
import { redisConnection } from '../lib/redis';

export const imageGenerationQueue = new Queue('image-generation', {
  connection: redisConnection,
  defaultJobOptions: {
    attempts: 3,
    backoff: {
      type: 'exponential',
      delay: 1000,
    },
    removeOnComplete: {
      age: 86400,
    },
    removeOnFail: {
      age: 86400,
    },
  },
});
```

### 6.2 Worker配置

- **并发数**: 根据服务器资源配置并发数
- **处理器分离**: 将处理器逻辑放在单独的文件中
- **事件监听**: 监听`completed`/`failed`事件

```typescript
import { Worker } from 'bullmq';
import { processor } from './processor';
import { redisConnection } from '../lib/redis';

export const worker = new Worker('image-generation', processor, {
  connection: redisConnection,
  concurrency: 4,
});

worker.on('completed', (job) => {
  console.log(`Job ${job.id} completed`);
});

worker.on('failed', (job, err) => {
  console.error(`Job ${job.id} failed: ${err.message}`);
});
```

## 7. 工具层规范

### 7.1 工具函数设计

- **纯函数优先**: 优先使用纯函数，避免副作用
- **无状态**: 工具函数不应依赖全局状态
- **单一职责**: 每个函数只做一件事

```typescript
export function formatFileSize(bytes: number): string {
  if (bytes === 0) return '0 B';
  
  const k = 1024;
  const sizes = ['B', 'KB', 'MB', 'GB'];
  const i = Math.floor(Math.log(bytes) / Math.log(k));
  
  return parseFloat((bytes / Math.pow(k, i)).toFixed(2)) + ' ' + sizes[i];
}
```

### 7.2 配置管理

- **集中管理**: 所有配置在`src/lib/config.ts`中管理
- **类型定义**: 使用TypeScript定义配置类型
- **默认值**: 为配置项提供合理的默认值


## 8. 测试规范

### 8.1 测试文件命名

- **单元测试**: `*.test.ts`
- **集成测试**: `*.test.ts`（放在`tests/integration`目录）
- **E2E测试**: `*.spec.ts`（放在`e2e`目录）

### 8.2 测试编写规范

- **AAA模式**: Arrange-Act-Assert模式
- **测试名称**: 描述性名称，说明测试目的和预期结果
- **隔离性**: 每个测试独立，使用`beforeEach/afterEach`清理

```typescript
describe('PromptService', () => {
  let service: PromptService;
  
  beforeEach(() => {
    service = new PromptService(mockApiClient);
  });
  
  it('should return refined prompt for valid input', async () => {
    const result = await service.refine('cat');
    expect(result).toBe('A cute cat');
  });
  
  it('should return original prompt on API failure', async () => {
    mockApiClient.post.mockRejectedValue(new Error('API error'));
    const result = await service.refine('cat');
    expect(result).toBe('cat');
  });
});
```

## 10. Git规范

### 10.1 提交信息规范

使用Conventional Commits格式：

```
<type>(<scope>): <description>

<body>

<footer>
```

**类型**:
- `feat`: 新功能
- `fix`: Bug修复
- `docs`: 文档更新
- `style`: 代码格式调整
- `refactor`: 重构
- `test`: 测试
- `chore`: 构建/工具更新

**示例**:
```
feat(prompt-service): add prompt refinement logic

- Implement prompt analysis
- Integrate with LLM API
- Add error handling

Closes #123
```

### 10.2 分支管理

- `main`: 主分支，生产环境代码
- `develop`: 开发分支，整合所有功能
- `feature/*`: 功能分支，开发新功能
- `bugfix/*`: Bug修复分支
- `hotfix/*`: 紧急修复分支

**流程**:
1. 从`develop`创建功能分支
2. 开发完成后提交Pull Request
3. 代码审查通过后合并到`develop`
4. 测试通过后合并到`main`
