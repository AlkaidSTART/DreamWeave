# 项目约束 - 架构约束

## 1.1 分层架构约束

| 层级 | 职责边界 | 约束条件 |
|------|----------|----------|
| 前端层 | UI展示、用户交互、状态管理 | 仅通过API层与后端通信，禁止直接访问Redis/外部服务 |
| API层 | 请求路由、参数验证、响应格式化 | 不包含业务逻辑，仅作为请求转发层 |
| 队列层 | 任务管理、并发控制、重试机制 | 所有异步任务必须通过BullMQ处理 |
| 服务层 | 业务逻辑、外部API调用、数据处理 | 禁止直接操作文件系统，通过存储抽象层访问 |
| 工具层 | 通用工具函数、配置管理 | 无状态设计，禁止依赖全局变量 |

## 1.2 数据流向约束

```
用户请求 → Next.js Client Component → Route Handler → Queue → Worker → External Service → Queue → Route Handler → Client Component
```

**约束**:
- 所有外部服务调用必须在Worker进程中执行，禁止在API层直接调用
- 任务状态必须通过Redis/BullMQ存储，禁止使用内存存储
- 图片文件必须通过存储抽象层访问，禁止直接操作文件路径

## 1.3 状态管理约束

| 状态类型 | 存储位置 | 保留期限 |
|----------|----------|----------|
| 任务状态 | Redis/BullMQ | 7天 |
| 生成结果 | 文件系统/对象存储 | 7天 |
| 上传文件 | 文件系统/对象存储 | 24小时 |
| 历史记录 | Redis List | 100条（可配置） |
