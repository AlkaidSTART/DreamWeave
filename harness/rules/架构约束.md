# Dreamweave AI 生图平台 - 架构约束文档

## 1. 系统架构约束

### 1.1 架构风格

**约束**: 采用分层单体架构（Layered Monolith）

```
┌─────────────────────────────────────────────────────────────────┐
│                        前端层 (Next.js)                          │
│  Server Components + Client Components                          │
└───────────────────┬─────────────────────────────────────────────┘
                    │ HTTP/REST
                    ▼
┌─────────────────────────────────────────────────────────────────┐
│                        API层 (Route Handlers)                    │
│  请求路由、参数验证、响应格式化                                    │
└───────────────────┬─────────────────────────────────────────────┘
                    │ BullMQ
                    ▼
┌─────────────────────────────────────────────────────────────────┐
│                      队列层 (BullMQ + Redis)                      │
│  任务管理、并发控制、重试机制                                      │
└───────────────────┬─────────────────────────────────────────────┘
                    │ 外部API调用
                    ▼
┌─────────────────────────────────────────────────────────────────┐
│                      外部服务层                                  │
│  AI生图API + 大模型API                                          │
└─────────────────────────────────────────────────────────────────┘
```

**约束说明**:
- 禁止跳过中间层直接访问下层服务
- API层禁止直接调用外部服务，必须通过队列层
- 前端层禁止直接访问Redis或外部服务

### 1.2 模块划分约束

| 模块 | 路径 | 职责 | 约束 |
|------|------|------|------|
| 前端页面 | `app/` | 用户界面、页面路由 | Server Components默认 |
| API路由 | `app/api/` | REST API端点 | 无业务逻辑 |
| 队列配置 | `src/queue/` | Queue和Worker配置 | 必须使用BullMQ |
| 服务层 | `src/services/` | 业务逻辑、外部调用 | 禁止直接操作文件系统 |
| Skill层 | `src/skills/` | 提示词模板管理 | 无状态设计 |
| 工具库 | `src/lib/` | 通用工具、配置管理 | 无副作用 |
| 类型定义 | `src/types/` | TypeScript类型定义 | 严格类型检查 |

## 2. 组件交互约束

### 2.1 前端组件交互

**约束**:
- Server Components负责数据获取和静态渲染
- Client Components负责用户交互和状态管理
- Server Components可以导入Client Components，反之不行
- 组件间通信通过Props传递，禁止使用全局状态

**示例**:
```tsx
// Server Component (数据获取)
async function ImageGenerationPage() {
  const skills = await getSkills();
  return <GenerationForm skills={skills} />;
}

// Client Component (用户交互)
'use client';

function GenerationForm({ skills }) {
  const [prompt, setPrompt] = useState('');
  const handleSubmit = async () => {
    await fetch('/api/generate', {
      method: 'POST',
      body: JSON.stringify({ prompt }),
    });
  };
  return <form onSubmit={handleSubmit}>...</form>;
}
```

### 2.2 API层与队列层交互

**约束**:
- API层只能向队列添加任务，不能直接处理任务
- 任务状态查询必须通过Redis/BullMQ
- SSE实时进度推送必须使用BullMQ的事件机制

**流程**:
```
POST /api/generate → Queue.add() → 返回jobId
GET /api/jobs/:id → Job.get() → 返回任务状态
GET /api/jobs/:id/stream → SSE订阅 → 推送进度事件
```

### 2.3 Worker与外部服务交互

**约束**:
- 所有外部API调用必须在Worker进程中执行
- Worker必须处理外部API的失败和超时
- 任务进度必须实时更新到Redis

**流程**:
```
Worker.process() → PromptService.refine() → AI生图API → 保存结果 → 更新进度
```

## 3. 数据流约束

### 3.1 请求数据流

**文生图数据流**:
```
用户输入提示词 → 前端验证 → POST /api/generate → Queue.add() → 返回jobId
                                                              │
                                                              ▼
                                                    Worker.process() → PromptService.refine()
                                                              │
                                                              ▼
                                                    AI生图API.generate() → 保存图片 → 更新进度
                                                              │
                                                              ▼
                                                    前端轮询/SSE → 获取结果 → 展示图片
```

**图生图数据流**:
```
用户上传图片 → POST /api/upload → 保存文件 → 返回图片URL
                                                              │
用户输入提示词 → 前端验证 → POST /api/generate (含图片URL) → Queue.add() → 返回jobId
                                                                                    │
                                                                                    ▼
                                                                          Worker.process() → AI生图API.generateWithImage()
                                                                                    │
                                                                                    ▼
                                                                          保存图片 → 更新进度 → 前端获取结果
```

### 3.2 数据存储约束

| 数据类型 | 存储方式 | 存储位置 | 约束 |
|----------|----------|----------|------|
| 任务状态 | Key-Value | Redis Hash | 任务ID作为Key |
| 任务队列 | Queue | BullMQ | 必须持久化 |
| 生成结果 | 文件 | 文件系统/对象存储 | 按任务ID分目录 |
| 上传文件 | 文件 | 文件系统/对象存储 | 临时存储24小时 |
| 历史记录 | List | Redis List | 限制100条 |

### 3.3 文件存储结构约束

```
public/
└── uploads/
    ├── [jobId]/
    │   ├── input/          # 上传的输入图片（图生图）
    │   │   └── original.png
    │   └── output/         # 生成的结果图片
    │       ├── img-1.png
    │       ├── img-2.png
    │       ├── img-3.png
    │       └── img-4.png
    └── temp/               # 临时文件（定期清理）
```

**约束**:
- 每个任务必须使用独立目录
- 文件名必须使用UUID或安全字符
- 禁止使用用户提供的原始文件名
- 临时文件必须在24小时内清理

## 4. 外部依赖约束

### 4.1 外部服务依赖

| 服务 | 依赖类型 | 约束 |
|------|----------|------|
| AI生图API | 核心依赖 | 必须处理API限流和失败 |
| 大模型API | 核心依赖 | 必须处理API限流和失败 |
| Redis | 基础设施依赖 | 必须配置连接重试 |

### 4.2 依赖版本约束

| 依赖 | 版本范围 | 更新策略 |
|------|----------|----------|
| Next.js | ^16.0.0 | 小版本自动更新，大版本手动评估 |
| React | ^19.0.0 | 小版本自动更新，大版本手动评估 |
| Tailwind CSS | ^4.0.0 | 小版本自动更新，大版本手动评估 |
| BullMQ | ^5.0.0 | 小版本自动更新，大版本手动评估 |
| ioredis | ^5.0.0 | 小版本自动更新，大版本手动评估 |
| Sharp | ^0.33.0 | 小版本自动更新，大版本手动评估 |

### 4.3 依赖注入约束

**约束**:
- 所有外部依赖必须通过构造函数注入
- 禁止使用全局单例模式
- 测试时必须能够替换依赖为Mock

**示例**:
```typescript
class ImageService {
  constructor(
    private apiClient: ApiClient,
    private storage: StorageService
  ) {}
  
  async generate(prompt: string): Promise<string[]> {
    const results = await this.apiClient.generate(prompt);
    return await this.storage.save(results);
  }
}
```

## 5. 扩展性约束

### 5.1 水平扩展约束

**约束**:
- 前端层支持水平扩展（无状态）
- API层支持水平扩展（无状态）
- Worker层支持水平扩展（通过Redis共享状态）
- 文件存储必须支持分布式存储（云对象存储）

**扩展策略**:
```
┌─────────────────────────────────────────────────────────────────┐
│                        负载均衡器                                │
└───────────┬─────────────────────────────┬───────────────────────┘
            │                             │
            ▼                             ▼
┌───────────────────────┐    ┌───────────────────────┐
│   Next.js实例1        │    │   Next.js实例2        │
│   (API + 前端)        │    │   (API + 前端)        │
└───────────┬───────────┘    └───────────┬───────────┘
            │                             │
            └───────────────┬─────────────┘
                            ▼
                  ┌─────────────────┐
                  │   Redis Cluster │
                  │   (共享状态)     │
                  └────────┬────────┘
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
   ┌───────────┐     ┌───────────┐     ┌───────────┐
   │ Worker 1  │     │ Worker 2  │     │ Worker N  │
   │ (处理任务) │     │ (处理任务) │     │ (处理任务) │
   └───────────┘     └───────────┘     └───────────┘
```

### 5.2 功能扩展约束

**约束**:
- 新增功能必须遵循现有模块划分
- 新增Skill模板必须在`src/skills/templates/`目录下
- 新增API端点必须在`app/api/`目录下
- 新增服务类必须在`src/services/`目录下

**扩展流程**:
1. 分析需求，确定模块归属
2. 设计接口和类型定义
3. 实现核心逻辑
4. 编写单元测试
5. 集成测试验证

### 5.3 技术扩展约束

**约束**:
- 新增技术栈必须经过架构评审
- 新增第三方库必须评估安全性和维护状态
- 禁止引入过多的依赖库（保持精简）

## 6. 安全架构约束

### 6.1 网络安全约束

**约束**:
- 生产环境必须使用HTTPS
- API接口必须配置CORS
- 禁止在前端暴露敏感信息（API密钥等）
- 外部服务调用必须在后端执行

### 6.2 输入安全约束

**约束**:
- 所有用户输入必须验证
- 禁止信任用户提供的文件名
- 必须过滤特殊字符和危险输入
- 文件上传必须验证文件类型和大小

**验证流程**:
```
用户输入 → 前端验证 → 后端验证 → 业务处理
```

### 6.3 数据安全约束

**约束**:
- API密钥必须使用环境变量存储
- 禁止在日志中记录敏感信息
- 生成的图片必须存储在安全位置
- 历史记录必须定期清理

---

## 7. 可观测性约束

### 7.1 日志约束

**约束**:
- 日志必须包含时间戳、日志级别、模块名称
- 错误日志必须包含堆栈信息
- 禁止记录敏感信息
- 日志格式必须统一（JSON格式）

**日志级别**:
- `debug`: 调试信息（仅开发环境）
- `info`: 一般信息（正常操作）
- `warn`: 警告信息（需要关注）
- `error`: 错误信息（需要处理）

### 7.2 监控约束

**约束**:
- 必须监控系统资源使用（CPU、内存、磁盘）
- 必须监控API响应时间和错误率
- 必须监控队列长度和任务状态
- 必须设置告警阈值

**监控指标**:
| 指标 | 告警阈值 |
|------|----------|
| CPU使用率 | > 80% |
| 内存使用率 | > 90% |
| API错误率 | > 5% |
| 队列长度 | > 100 |
| 任务失败率 | > 10% |

### 7.3 追踪约束

**约束**:
- 每个请求必须有唯一的追踪ID
- 追踪ID必须在所有日志中传递
- 支持分布式追踪（可选）

## 8. 部署架构约束

### 8.1 环境约束

| 环境 | 配置要求 | 约束 |
|------|----------|------|
| 开发 | 本地环境，Redis本地 | 允许跳过部分安全检查 |
| 测试 | 独立环境，Redis独立 | 必须通过所有测试 |
| 生产 | 云环境，Redis集群 | 必须启用所有安全检查 |

### 8.2 容器化约束

**约束**:
- 应用必须支持Docker容器化部署
- Docker镜像必须使用多阶段构建
- 容器必须以非root用户运行
- 必须设置资源限制

**Dockerfile示例**:
```dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production

FROM node:20-alpine
WORKDIR /app
COPY --from=builder /app/node_modules ./node_modules
COPY . .
USER node
ENV NODE_ENV=production
EXPOSE 3000
CMD ["npm", "start"]
```

### 8.3 进程管理约束

**约束**:
- 主进程和Worker进程必须独立部署
- 进程必须配置自动重启
- 必须监控进程健康状态
- 必须配置优雅关闭

**PM2配置示例**:
```json
{
  "apps": [
    {
      "name": "dreamweave-app",
      "script": "node_modules/.bin/next start",
      "instances": "max",
      "exec_mode": "cluster",
      "env": { "NODE_ENV": "production" }
    },
    {
      "name": "dreamweave-worker",
      "script": "worker.js",
      "instances": 4,
      "exec_mode": "fork",
      "env": { "NODE_ENV": "production" }
    }
  ]
}
```

## 9. 容错架构约束

### 9.1 故障处理约束

**约束**:
- 所有外部调用必须有超时设置
- 所有外部调用必须有重试机制
- 任务失败必须记录错误信息
- 必须提供重试和取消任务的功能

### 9.2 降级策略

**约束**:
- 外部服务不可用时，必须提供降级方案
- 降级方案必须提前定义和测试
- 降级状态必须通知用户

**降级场景**:
| 场景 | 降级策略 | 用户通知 |
|------|----------|----------|
| AI生图API不可用 | 返回错误提示 | "服务暂时不可用，请稍后重试" |
| 大模型API不可用 | 使用原始提示词 | "提示词优化暂时不可用，将使用原始提示词" |
| Redis不可用 | 拒绝新请求 | "服务暂时不可用，请稍后重试" |

### 9.3 数据一致性约束

**约束**:
- 任务状态和文件存储必须保持一致
- 任务失败时必须清理已生成的文件
- 必须定期检查不一致状态并修复

## 11. 性能架构约束

### 11.1 缓存约束

**约束**:
- 常用数据（Skill模板、配置）必须缓存
- 缓存必须有过期时间
- 缓存失效必须有策略

**缓存策略**:
| 数据类型 | 缓存时间 | 失效策略 |
|----------|----------|----------|
| Skill模板 | 1小时 | 手动刷新 |
| 任务状态 | 5秒 | 自动过期 |
| 生成结果 | 永久 | 文件删除时失效 |

### 11.2 资源优化约束

**约束**:
- 图片必须优化（压缩、格式转换）
- 前端代码必须按需加载
- 静态资源必须使用CDN（生产环境）
- 必须启用HTTP缓存

### 11.3 并发控制约束

**约束**:
- Worker并发数必须根据服务器资源配置
- API请求必须限流
- 同时生成的图片数量必须限制（1-4张）

### 12.1 数据隐私约束

**约束**:

- 必须提供用户数据删除功能

### 12.2 内容安全约束

**约束**:
- 必须过滤违规内容的生成请求
- 必须监控生成结果的内容安全
- 必须提供内容举报机制

### 12.3 知识产权约束

**约束**:
- 用户必须保证输入内容的合法性
- 平台对生成内容的知识产权归属必须明确
- 必须提供使用条款和隐私政策
