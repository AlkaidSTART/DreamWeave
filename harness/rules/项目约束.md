# Dreamweave AI 生图平台 - 项目约束文档

## 1. 架构约束

### 1.1 分层架构约束

| 层级 | 职责边界 | 约束条件 |
|------|----------|----------|
| 前端层 | UI展示、用户交互、状态管理 | 仅通过API层与后端通信，禁止直接访问Redis/外部服务 |
| API层 | 请求路由、参数验证、响应格式化 | 不包含业务逻辑，仅作为请求转发层 |
| 队列层 | 任务管理、并发控制、重试机制 | 所有异步任务必须通过BullMQ处理 |
| 服务层 | 业务逻辑、外部API调用、数据处理 | 禁止直接操作文件系统，通过存储抽象层访问 |
| 工具层 | 通用工具函数、配置管理 | 无状态设计，禁止依赖全局变量 |

### 1.2 数据流向约束

```
用户请求 → Next.js Client Component → Route Handler → Queue → Worker → External Service → Queue → Route Handler → Client Component
```

**约束**:
- 所有外部服务调用必须在Worker进程中执行，禁止在API层直接调用
- 任务状态必须通过Redis/BullMQ存储，禁止使用内存存储
- 图片文件必须通过存储抽象层访问，禁止直接操作文件路径

### 1.3 状态管理约束

| 状态类型 | 存储位置 | 保留期限 |
|----------|----------|----------|
| 任务状态 | Redis/BullMQ | 7天 |
| 生成结果 | 文件系统/对象存储 | 7天 |
| 上传文件 | 文件系统/对象存储 | 24小时 |
| 历史记录 | Redis List | 100条（可配置） |

## 2. 编码规范约束

### 2.1 语言规范

- **TypeScript**: 项目必须使用TypeScript，禁止使用JavaScript
- **严格模式**: `tsconfig.json`必须启用`strict: true`
- **ESLint**: 必须通过ESLint检查，禁止跳过lint规则

### 2.2 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件 | 小写+连字符 | `prompt-service.ts` |
| 组件 | PascalCase | `TextToImageForm.tsx` |
| 函数 | camelCase | `generateImage()` |
| 变量 | camelCase | `imageCount` |
| 常量 | UPPER_SNAKE_CASE | `MAX_FILE_SIZE` |
| 类型/接口 | PascalCase | `GenerationJob` |
| 枚举 | PascalCase | `JobStatus` |

### 2.3 组件规范

- **Server Components**: 默认使用服务端组件，仅在需要交互时使用`'use client'`
- **组件职责**: 单一职责原则，组件代码不超过200行
- **Props定义**: 必须使用TypeScript接口定义Props
- **无副作用**: Server Components禁止使用useState/useEffect

### 2.4 API规范

- **RESTful风格**: API路径使用名词复数，HTTP方法使用标准语义
- **错误处理**: 统一错误响应格式，包含error和message字段
- **状态码**: 使用标准HTTP状态码（200/400/404/500）
- **响应格式**: 统一JSON响应格式

## 3. 测试约束

### 3.1 测试框架

- **单元测试**: 使用Vitest，Jest兼容模式
- **集成测试**: 使用Vitest + Supertest
- **E2E测试**: 使用Playwright

### 3.2 测试覆盖率

| 层级 | 覆盖率目标 | 强制要求 |
|------|------------|----------|
| 单元测试 | 80%+ | 是 |
| 集成测试 | 核心流程覆盖 | 是 |
| E2E测试 | 关键用户路径 | 是 |

### 3.3 测试隔离

- 每个测试用例必须独立，互不影响
- 使用`beforeEach/afterEach`清理测试数据
- 测试数据库使用ioredis-mock模拟
- 外部服务使用MSW拦截

### 3.4 测试执行

- **开发阶段**: 每次提交前必须通过单元测试
- **CI/CD阶段**: 必须通过所有测试才能部署
- **测试命令**: 统一使用`npm test`系列命令

## 4. 部署约束

### 4.1 环境要求

| 环境 | Node.js | Redis | 存储 |
|------|---------|-------|------|
| 开发 | 20.x+ | 7.x+ | 本地存储 |
| 测试 | 20.x+ | 7.x+ | 本地存储 |
| 生产 | 20.x+ | 7.x+ | 云对象存储 |

### 4.2 配置管理

- 所有敏感配置必须使用环境变量
- 禁止硬编码任何配置值
- `.env`文件必须包含在`.gitignore`中
- 配置项必须在`src/lib/config.ts`中统一管理

### 4.3 进程管理

- **主进程**: Next.js应用进程
- **Worker进程**: 独立的BullMQ Worker进程
- **进程监控**: 使用PM2或容器编排工具管理进程
- **自动重启**: 进程崩溃后必须自动重启

### 4.4 资源限制

| 资源 | 限制 | 监控指标 |
|------|------|----------|
| 内存 | 1GB | RSS内存使用 |
| CPU | 4核 | CPU使用率 |
| 并发连接 | 100 | 活跃连接数 |
| 文件大小 | 10MB | 上传文件大小 |

## 5. 安全约束

### 5.1 输入验证

| 验证项 | 约束 |
|--------|------|
| 提示词长度 | 1-2000字符 |
| 图片格式 | jpg/jpeg/png/gif/webp |
| 图片大小 | ≤10MB |
| 文件命名 | 禁止特殊字符，使用UUID |

### 5.2 API安全

- **限流**: 每个IP每分钟最多10次生成请求
- **认证**: 生产环境必须添加API密钥认证
- **CORS**: 限制允许的Origin
- **请求体限制**: 最大1MB

### 5.3 文件安全

- **文件类型检查**: 校验文件magic number，不依赖扩展名
- **路径遍历防护**: 禁止`..`等路径遍历字符
- **文件存储隔离**: 每个任务使用独立目录
- **定时清理**: 超过7天的文件自动清理

### 5.4 数据安全

- **API密钥**: 环境变量存储，禁止日志输出
- **传输加密**: 生产环境必须使用HTTPS
- **敏感信息**: 禁止存储用户输入的原始提示词（可选）

## 7. 错误处理约束

### 7.1 错误分类

| 错误类型 | 处理方式 | 用户反馈 |
|----------|----------|----------|
| 用户输入错误 | 返回400状态码 | 明确的错误提示 |
| 服务端错误 | 返回500状态码 | 通用错误提示 |
| 外部服务错误 | 任务标记为failed | 显示重试按钮 |
| 网络错误 | 自动重试（最多3次） | 显示加载状态 |

### 7.2 错误日志

- 所有错误必须记录到日志
- 日志级别：debug/info/warn/error
- 错误日志必须包含：时间、错误类型、错误消息、堆栈信息
- 禁止记录敏感信息（API密钥、用户输入等）

### 7.3 重试策略

| 场景 | 重试次数 | 重试间隔 |
|------|----------|----------|
| Redis连接失败 | 无限重试 | 指数退避 |
| 外部API调用失败 | 3次 | 指数退避 |
| 文件操作失败 | 2次 | 1秒间隔 |

## 10. 变更管理约束

### 10.1 变更流程

```
需求分析 → 设计评审 → 代码实现 → 单元测试 → 代码审查 → 集成测试 → 部署 → 验证
```

### 10.2 变更类型

| 类型 | 审批要求 | 测试要求 |
|------|----------|----------|
| Bug修复 | 1人审查 | 单元测试 |
| 功能增强 | 2人审查 | 单元测试+集成测试 |
| 架构变更 | 架构评审 | 全量测试 |
| 依赖升级 | 1人审查 | 全量测试 |

### 10.3 回滚策略

- 所有部署必须支持快速回滚
- 回滚必须在5分钟内完成
- 回滚后必须验证核心功能正常
