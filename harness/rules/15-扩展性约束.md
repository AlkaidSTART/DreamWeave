# 架构约束 - 扩展性约束

## 5.1 水平扩展约束

**约束**:
- 前端层支持水平扩展（无状态）
- API层支持水平扩展（无状态）
- Worker层支持水平扩展（通过Redis共享状态）
- 文件存储必须支持分布式存储（云对象存储）

**扩展策略**:
```
┌─────────────────────────────────────────────────────────────────┐
│                        负载均衡器                                │
└───────────┬─────────────────────────────┬───────────────────────┘
            │                             │
            ▼                             ▼
┌───────────────────────┐    ┌───────────────────────┐
│   Next.js实例1        │    │   Next.js实例2        │
│   (API + 前端)        │    │   (API + 前端)        │
└───────────┬───────────┘    └───────────┬───────────┘
            │                             │
            └───────────────┬─────────────┘
                            ▼
                  ┌─────────────────┐
                  │   Redis Cluster │
                  │   (共享状态)     │
                  └────────┬────────┘
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
   ┌───────────┐     ┌───────────┐     ┌───────────┐
   │ Worker 1  │     │ Worker 2  │     │ Worker N  │
   │ (处理任务) │     │ (处理任务) │     │ (处理任务) │
   └───────────┘     └───────────┘     └───────────┘
```

## 5.2 功能扩展约束

**约束**:
- 新增功能必须遵循现有模块划分
- 新增Skill模板必须在`src/skills/templates/`目录下
- 新增API端点必须在`app/api/`目录下
- 新增服务类必须在`src/services/`目录下

**扩展流程**:
1. 分析需求，确定模块归属
2. 设计接口和类型定义
3. 实现核心逻辑
4. 编写单元测试
5. 集成测试验证

## 5.3 技术扩展约束

**约束**:
- 新增技术栈必须经过架构评审
- 新增第三方库必须评估安全性和维护状态
- 禁止引入过多的依赖库（保持精简）
