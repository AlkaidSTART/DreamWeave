# 阶段 04: 测试验证

## 目标

执行完整的验证流程，确保代码质量和功能正确性。

## 触发条件

- 代码实现完成
- 需要验证功能正确性

## 操作步骤

### 步骤 1: Lint检查

```bash
npm run lint
```

**要求**: 无错误，警告可接受但应尽量修复

### 步骤 2: 类型检查

```bash
npm run typecheck
```

**要求**: 无TypeScript错误

### 步骤 3: 构建验证

```bash
npm run build
```

**要求**: 构建成功，无错误

### 步骤 4: 单元测试

```bash
npm run test:unit
```

**要求**: 
- 所有测试通过
- 测试覆盖率≥80%

### 步骤 5: 集成测试（可选）

```bash
npm run test:integration
```

**要求**: 核心流程测试通过

### 步骤 6: E2E测试（可选）

```bash
npm run test:e2e
```

**要求**: 关键用户路径测试通过

### 步骤 7: 接口验证（后端）

```bash
# 使用curl或API工具验证接口
curl -X POST http://localhost:3000/api/generate \
  -H "Content-Type: application/json" \
  -d '{"prompt": "test"}'
```

**要求**: 
- API响应格式正确
- 状态码符合预期
- 错误处理正常

### 步骤 8: UI验证（前端）

```bash
# 启动开发服务器
npm run dev
```

**要求**: 
- 页面正常加载
- 交互功能正常
- 响应式布局正确
- 无控制台错误

## 验证检查清单

| 验证项 | 命令 | 状态 |
|--------|------|------|
| Lint检查 | `npm run lint` | ✅/❌ |
| 类型检查 | `npm run typecheck` | ✅/❌ |
| 构建验证 | `npm run build` | ✅/❌ |
| 单元测试 | `npm run test:unit` | ✅/❌ |
| 集成测试 | `npm run test:integration` | ✅/❌（可选） |
| E2E测试 | `npm run test:e2e` | ✅/❌（可选） |
| API接口验证 | curl/postman | ✅/❌（后端） |
| UI功能验证 | 浏览器访问 | ✅/❌（前端） |

## 失败处理

如果任何验证步骤失败：

1. 定位失败原因
2. 修复代码
3. 重新执行验证
4. 直到所有验证通过

## 输出产物

| 产物 | 说明 |
|------|------|
| 验证报告 | 各验证步骤的结果 |
| 测试报告 | 测试覆盖率报告 |
