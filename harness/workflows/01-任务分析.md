# 阶段 01: 任务分析

## 目标

根据用户输入，识别任务类型、类别和优先级，确定开发方向。

## 触发条件

- 收到新需求
- 收到Bug报告
- 收到代码优化请求

## 操作步骤

### 步骤 1: 识别任务类型

| 类型 | 关键词 | 描述 | 下一步 |
|------|--------|------|--------|
| **前端开发** | 页面、组件、交互、样式、UI | UI界面开发、用户交互实现 | 进入02-Agent选择 |
| **后端开发** | API、服务、队列、Redis、接口 | API路由、业务逻辑、任务队列 | 进入02-Agent选择 |
| **功能开发** | 功能、新特性、需求 | 完整功能开发流程 | 进入02-Agent选择 |
| **Bug修复** | Bug、错误、问题、修复 | 定位并修复代码缺陷 | 进入02-Agent选择 |
| **测试验证** | 测试、验证、覆盖率 | 编写测试、验证功能 | 进入02-Agent选择 |
| **代码优化** | 重构、优化、性能、改进 | 代码质量改进、性能提升 | 进入02-Agent选择 |

### 步骤 2: 确定任务类别

| 类别 | 说明 | 示例 | 处理优先级 |
|------|------|------|----------|
| **P0 - 紧急** | 核心功能、严重Bug | 登录失败、页面崩溃、服务不可用 | 立即处理 |
| **P1 - 重要** | 功能增强、一般Bug | 新增按钮、UI优化、接口错误 | 优先处理 |
| **P2 - 常规** | 优化改进、技术债务 | 代码重构、文档更新、性能优化 | 按计划处理 |

### 步骤 3: 分析任务范围

```
任务分析表:
┌─────────────────┬───────────────────────────────────────┐
│ 任务类型         │ 前端开发 / 后端开发 / 功能开发 / ...   │
├─────────────────┼───────────────────────────────────────┤
│ 任务类别         │ P0 / P1 / P2                          │
├─────────────────┼───────────────────────────────────────┤
│ 涉及模块         │ 列出涉及的文件或目录                   │
├─────────────────┼───────────────────────────────────────┤
│ 依赖关系         │ 是否依赖其他模块或服务                  │
├─────────────────┼───────────────────────────────────────┤
│ 预期工作量       │ 小时 / 天 / 周                        │
└─────────────────┴───────────────────────────────────────┘
```

### 步骤 4: 确定开发方向

根据任务分析，确定：
1. 需要哪些Agent参与
2. 需要遵循哪些约束文档
3. 大致的开发计划

## 输出产物

| 产物 | 说明 |
|------|------|
| 任务分析表 | 任务类型、类别、范围 |
| Agent选择建议 | 推荐使用的Agent |
