# 阶段 05: 代码审查

## 目标

审查代码质量，确保符合规范和约束。

## 触发条件

- 测试验证通过
- 需要审查代码变更

## 操作步骤

### 步骤 1: 创建Pull Request

1. 推送功能分支到远程仓库
2. 创建Pull Request到`develop`分支
3. 填写PR描述和关联Issue

### 步骤 2: 代码审查

#### 审查内容

| 审查项 | 检查内容 |
|--------|----------|
| 功能正确性 | 是否符合需求 |
| 代码质量 | 是否遵循编码规范 |
| 类型安全 | 是否有TypeScript错误 |
| 错误处理 | 是否有完善的错误处理 |
| 性能 | 是否有性能问题 |
| 安全性 | 是否有安全漏洞 |
| 测试覆盖 | 是否有足够的测试 |
| 文档 | 是否有完善的文档 |

#### 审查标准

| 问题类型 | 处理方式 |
|----------|----------|
| 严重问题 | 必须修复后才能合并 |
| 中等问题 | 建议修复，可协商 |
| 轻微问题 | 建议修复，可后续处理 |

### 步骤 3: 修复问题

1. 根据审查意见修改代码
2. 运行测试确保通过
3. 更新Pull Request

### 步骤 4: 合并代码

1. 确认所有问题已修复
2. 至少1人审查通过
3. 使用Squash Merge合并
4. 删除功能分支

## 输出产物

| 产物 | 说明 |
|------|------|
| 审查意见 | PR评论 |
| 合并记录 | Git提交 |
