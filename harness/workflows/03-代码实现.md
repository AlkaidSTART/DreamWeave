# 阶段 03: 代码实现

## 目标

根据设计文档实现功能，编写高质量代码。

## 触发条件

- 设计评审通过
- 需要实现新功能
- 需要修复Bug

## 操作步骤

### 步骤 1: 分支管理

| 分支类型 | 命名规范 | 用途 |
|----------|----------|------|
| 主分支 | `main` | 生产环境代码 |
| 开发分支 | `develop` | 整合所有功能 |
| 功能分支 | `feature/{name}` | 开发新功能 |
| Bug修复分支 | `bugfix/{name}` | 修复Bug |
| 紧急修复分支 | `hotfix/{name}` | 紧急修复 |

### 步骤 2: 环境准备

```bash
# 从develop创建功能分支
git checkout -b feature/my-feature

# 安装依赖
npm install

# 启动开发服务器
npm run dev
```

### 步骤 3: 代码编写

#### 编码规范

- 使用TypeScript严格模式
- 组件默认使用Server Components
- 所有公共函数添加JSDoc注释
- 遵循[编码规范](../rules/编码规范.md)

#### 错误处理

- 使用try-catch包裹异步操作
- 定义自定义错误类
- 向上传播错误
- 记录错误日志

#### 配置管理

- 使用环境变量存储配置
- 通过`src/lib/config.ts`管理配置
- 禁止硬编码配置值

### 步骤 4: 代码提交

#### Commit规范

使用Conventional Commits格式：

```
<type>(<scope>): <description>

<body>

<footer>
```

**类型**:
- `feat`: 新功能
- `fix`: Bug修复
- `docs`: 文档更新
- `style`: 代码格式调整
- `refactor`: 重构
- `test`: 测试
- `chore`: 构建/工具更新

## 输出产物

| 产物 | 说明 |
|------|------|
| 代码文件 | 实现功能的代码 |
| 测试文件 | 单元测试代码 |
| 提交记录 | Git提交 |
