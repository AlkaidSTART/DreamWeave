# 阶段 03: 代码实现

## 目标

根据任务分析和Agent定义，编写高质量代码，遵循约束规范。

## 触发条件

- Agent选择完成
- 已查阅相关约束文档

## 操作步骤

### 步骤 1: 分支管理

```bash
# 1. 切换到develop分支
git checkout develop
git pull origin develop

# 2. 创建功能分支
git checkout -b feature/my-feature

# 或创建Bug修复分支
git checkout -b bugfix/my-bugfix
```

| 分支类型 | 命名规范 | 用途 |
|----------|----------|------|
| feature/* | `feature/{name}` | 新功能开发 |
| bugfix/* | `bugfix/{name}` | Bug修复 |
| hotfix/* | `hotfix/{name}` | 紧急修复（从main创建） |

### 步骤 2: 环境准备

```bash
# 安装依赖
npm install

# 启动开发服务器
npm run dev
```

### 步骤 3: 代码编写

#### 遵循约束

| 约束类型 | 文档路径 |
|----------|----------|
| TypeScript规范 | `../rules/01-typescript规范.md` |
| 组件规范 | `../rules/02-组件规范.md` |
| API规范 | `../rules/03-API规范.md` |
| 样式规范 | `../rules/04-样式规范.md` |
| 服务层规范 | `../rules/05-服务层规范.md` |
| 队列层规范 | `../rules/06-队列层规范.md` |

#### 核心规则

1. **TypeScript严格模式**: 禁止使用`any`类型
2. **Server Components默认**: 组件默认使用Server Components
3. **错误处理**: 所有异步操作必须用try-catch包裹
4. **配置管理**: 通过`src/lib/config.ts`管理配置，禁止硬编码
5. **JSDoc注释**: 所有公共函数必须添加JSDoc注释

### 步骤 4: TDD开发

```bash
# 1. 先编写测试
npm run test:unit -- --run src/my-module.test.ts

# 2. 再实现功能
# ...

# 3. 验证测试通过
npm run test:unit -- --run src/my-module.test.ts
```

### 步骤 5: 中间验证

```bash
# 随时检查代码质量
npm run lint
npm run typecheck
```

## 输出产物

| 产物 | 说明 |
|------|------|
| 代码文件 | 实现功能的代码 |
| 测试文件 | 单元测试代码 |
| 提交记录 | Git提交 |
