# 阶段 05: 代码提交

## 目标

所有验证通过后，完善提交信息并推送到远程develop分支。

## 触发条件

- 所有测试验证通过（Lint、TypeCheck、Build、Test）

## 操作步骤

### 步骤 1: 查看变更

```bash
git status
git diff
```

**要求**: 确认变更内容正确，无意外修改

### 步骤 2: 暂存文件

```bash
git add .
```

**要求**: 只暂存需要提交的文件，避免提交临时文件

### 步骤 3: 编写提交信息

使用Conventional Commits格式：

```
<type>(<scope>): <description>

<body>

<footer>
```

**类型说明**:

| 类型 | 说明 | 示例 |
|------|------|------|
| feat | 新功能 | `feat(api): add generate endpoint` |
| fix | Bug修复 | `fix(frontend): resolve form validation` |
| docs | 文档更新 | `docs(readme): update installation guide` |
| style | 代码格式调整 | `style: fix indentation` |
| refactor | 重构 | `refactor(service): simplify logic` |
| test | 测试 | `test: add unit tests` |
| chore | 构建/工具更新 | `chore: update dependencies` |

**提交示例**:

```
feat(prompt-service): add prompt refinement logic

- Implement prompt analysis with LLM API
- Add error handling for API failures
- Add unit tests for all methods

Closes #123
```

### 步骤 4: 提交代码

```bash
git commit -m "feat(feature-name): description"
```

**要求**: 提交信息清晰、简洁、符合规范

### 步骤 5: 推送到远程分支

```bash
git push origin feature/my-feature
```

**要求**: 推送到对应的功能分支

### 步骤 6: 发起Pull Request

在GitHub上：

1. 从功能分支向`develop`分支发起PR
2. 填写PR描述（功能说明、测试方法、相关Issue）
3. 添加审查人员

## 提交检查清单

| 检查项 | 状态 |
|--------|------|
| 所有验证通过 | ✅/❌ |
| 提交信息符合规范 | ✅/❌ |
| 无敏感信息提交 | ✅/❌ |
| 无临时文件提交 | ✅/❌ |
| 已推送到远程分支 | ✅/❌ |
| 已发起PR | ✅/❌ |

## 输出产物

| 产物 | 说明 |
|------|------|
| Git提交 | 代码变更记录 |
| Pull Request | 代码审查请求 |
